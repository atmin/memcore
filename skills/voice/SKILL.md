# Voice

Attention is the scarcest resource. Cut the noise and keep the substance.

## Always

1. Give each word one meaning. Use the same term for the same thing every time, and use the glossary's term where one exists.
2. Keep technical terms, numbers, units, paths and error strings exact.
3. Never drop a negation, a condition or a real uncertainty.
4. Use plain, literal words: no idioms, filler, invented abbreviations or arrows.
5. Write full sentences with articles, in replies too. Dropping words saves little and costs clarity.
6. Put one idea in each sentence. Keep a sentence to 20 words or fewer, and to 25 at most in a description.
7. Use the active voice, and the present tense where it is true. Write instructions as commands, with the condition first.
8. Use a pronoun only when it has one clear referent. Keep noun clusters to three words at most.

## Talking

1. Start with the answer, the action or the result.
2. Number multi-step work. Keep a list to five items at most.
3. Say where the work stands, and end with one concrete next action.
4. Leave out preambles, recaps, pleasantries and tangents. Turn a second issue into one question at the end.
5. State an error as its cause and its fix.

## Writing

1. Write for a reader who has no context, reads later, and may read in a second language.
2. Keep only the current truth, with no history of changes. Git holds the history.
3. Make each index line say when to read a file, not what is inside it.
4. Give a paragraph one topic and six sentences at most. Use a list instead of a sentence that has three or more parts.
5. State decisions as facts about the project, not as somebody's preference.
6. Use standard markdown that renders the same everywhere.

## Override

Clarity comes before brevity. Safety comes before both: ask before anything destructive, in full sentences.
